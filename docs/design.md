# michi の設計（2026-10-15 に確定）

持ち主が設計メモと HTML の画面イメージ（[mock/michi.html](mock/michi.html)、ブラウザで開いて窓を押してから `?`）で決めたこと。
迷ったら画面イメージを開いて同じ動きにする。画面イメージは tsumugi の本当の履歴（origin/main の新しい 130 件）に、
Claude が 3 つの worktree で作業している途中の作り話を重ねたもので、Git にも tsumugi にも触らない。
トーストと欄の小さい字が、実物で呼ぶ git・tsumugi のコマンドの見当。

画面イメージは 1 回目（樹形図・worktree の表・衝突の解消・ロゴ）まで。「変更」の画面（ステージとコミット）・ブランチ全体の差分・rebase は
2 回目で描き、段階 2「変える」の前に決める（[dev-prompt.md](dev-prompt.md)）。

## 作る理由

- lazygit: 差分が文字だけで単語の強調が弱い。衝突は ours/theirs を選ぶだけで base が見えない。覚えたキーでしか動かない。
- SourceTree: 重く、大きな履歴で止まる。衝突の解消は外部ツール頼み。rebase の途中が分かりにくい。
- どちらにも無いもの: 複数の worktree の状態の一覧、マージする前の衝突の予測、衝突の「双方の意図」、並べて動かす Claude の状態と、終えた作業の見直し。

## 画面の方針

1. **樹形図が主役。**最初に開く画面で、その場で差分を読める。
2. **マウスでも、キーでも。**操作は全部ボタンで届き、よく使うものだけキーを持つ。キーの一覧は `?`。
3. **取り返せる。**破壊的な操作の前に、何が失われるかを書く。reflog で戻せない変更は、操作の前に自動で退避する（「取り返せる」の節）。
4. **色に意味を持たせる。**ブランチの色は固定し、状態（衝突・未 push・worktree）は形で示す。

## 全体

- **1 つの窓が 1 つのリポジトリ**（全部の worktree を含む）。樹形図には全部の worktree を重ね、「変更」の画面は上で worktree を切り替える。
- 上から、タイトルバー・ビュー・キーの帯（keybar）。
- タイトルバー: 左にロゴと `michi` とビューのタブ、リポジトリの札（名前・`⎇ main · worktree 4`、マージ中は「· マージ中」を赤で）、
  パレットの欄（「コマンドを探す」`Ctrl+Shift+P`）、右に窓のボタン。
- ビューと数字のキー: `1` 樹形図（最初の画面）、`2` 変更（タブに未コミットのファイルの数）、`3` worktree、`,` 設定。
  `4` 衝突は、マージ・cherry-pick などで衝突している間だけタブが出る（「● 残りの数」、解けたら「✓」）。
- keybar: 左に今の画面で使えるキー（画面ごとに下の表）、右に「⟳ fetch 3 分前」・「Claude ● 1 ◐ 1 ✓ 1」（tsumugi の状態ごとの数）・
  時計（`2026/10/15 (Thu) 10:12`、ito の共通仕様の書き方）。
- 窓は **1280×800 が基準**。半分の幅（960）では、樹形図の詳しくを下に回して左の列を隠し、worktree の表はカードにし、
  衝突の画面は base の列を隠す（各箇所の「base を見る」で出す）。
- **スクロールバーは樹形図だけ**に細く付け、印を載せる（樹形図の節）。ほかの一覧は minato と同じく畳んで、バーを付けない。
- テーマは ito-theme（画面イメージでは tsumugi Dark・tsumugi Light・Tokyo Night・Nord）。窓の枠は tsumugi Dark の系統。

## 樹形図（`1`）

3 列: 左の列・樹形図・詳しく。

### 左の列

上から「worktree」（ブランチの色・名前・Claude の印・`↑N`、押すとその先頭へ）、「ブランチ」（`feat/`・`fix/` など `/` の前の名前で束にし、束は畳んでおく）、
「リモート」（origin、畳んでおく）、「タグ」、「stash」。ブランチを押すと、その先頭を選ぶ（畳んだ中なら開く）。

### 道具の帯と列の見出し

- 道具の帯: `⟳ fetch` `f`・`↓ pull` `p`・`↑ push` `P`｜`ブランチ` `b`・`stash` `s`・`＋ 新しい作業` `N`（強調）・絞りの欄（`/`、「絞る（説明・ハッシュ・名前）」と当たりの数）。
- 列の見出し: 樹形図・説明・作者・日時・コミット。「説明」の見出しの右に「PR を畳む `z`」の切り替え（`aria-pressed`）を置く。

### 描き方

- **レーン**: 一番左は main に固定する（worktree ごとに HEAD があるため）。ほかは先に見つかったブランチが左を取り、枝が閉じたら詰める。
- **色**: テーマの ANSI 16 色から、赤（1・9）と灰色（0・7・8・15）を除いて取る。main はシアン（6）。main と worktree のブランチに先に違う色を
  割り当て、ほかはブランチ名のハッシュで選ぶ（同じブランチは常に同じ色）。隣のレーンと同じになったら、後から来た方をずらす。
- **行**: 1 行が 1 コミットで、高さは固定。点・説明・作者・日時・短いハッシュ。説明の横に、ブランチ・タグ・origin の位置・worktree（`⧉`）を丸い札で出す。
  github-actions[bot] は `⚙` を付ける。
- **マージ**: 親が 2 つある点は二重の丸にし、2 本目の親へ曲線で戻る。
- **worktree**: 各 worktree の先頭に `⧉` の札と、そこにいる Claude の様子（● 実行中・◐ 待ち・✓ 済み）。
- **WIP**: まだコミットしていない変更は、worktree ごとに 1 行の点線の白丸で、その worktree の先頭の上に出す。
- **衝突の予測**: worktree どうし・ブランチと main を合わせてみてぶつかると分かった先頭に `⚠`。未コミットの変更を数えてぶつかるものは点線の枠で、WIP の行に付く。
- **見ていないコミット**: 青い点と太字。選ぶと消え、worktree の表の「見ていない」の数も減る。
- **長い履歴**: 画面に見える行だけ描き、残りは裏で読む（仮想スクロール）。下の「… さらに古い N 件」を押すと読み込む。
- **スクロールバー**: 右の細いバーが、樹形図のただ 1 つのスクロールの印。worktree の先頭・WIP・予測・タグ・絞りの当たり・選んでいる所が並び、
  押すとそこへ飛ぶ。つまみはドラッグできる。

### PR を畳む（`z`、既定で入）

- main の first-parent だけを見せ、マージで main に入ったコミットは、そのマージの行の「▸ N」（畳んだコミットの数）に畳む。左の短い線が、畳んだ枝が入ってきた印。
- いつも出したまま: worktree の先、まだ main に入っていないブランチ、札（ブランチ・タグ）の付いたコミット。
- 「▸ N」を押すか `l` で開き（「▾ N」になる）、`h` で畳む。`z` で全部を切り替え、トーストで知らせる
  （「main に入った 31 本のマージを畳みました（41 コミット）。」「マージを全部広げました。」）。
- マージの行を選ぶと、詳しくに「このマージで main に入った N コミット」を並べ、押すとそこへ飛ぶ。畳んだコミットへ飛ぶとき（左の列・絞り・リンク）は、そこだけ開く。

### 絞り（`/`）

説明・ハッシュ・名前で絞る。合わないコミットは消さずに薄くし、スクロールバーに当たりの印を付ける。`Enter` で次の当たり、`Esc` で消す。
残った行の親子の線はつないだまま。説明・作者・ハッシュ・ブランチ名とタグ名は、スペースで分けた語がすべて当たるコミット。
中身・パス・日付は git に聞く（最初に書いた 1 つだけ。その後ろの文字を全部使う。Enter で探す）:
`s:文字列`（`log -S`）・`g:正規表現`（`log -G`）・`p:パスの一部`（そのパスを変えたコミット。大小文字は見ない）・`d:開始..終了`（コミットの日付。片方は省ける。`..` が無ければ開始。`2026-10-01`・`2.weeks.ago` など git が読める書き方）。

### 詳しく

- コミット: 説明・ハッシュ・作者・日時・親（押すとそこへ）・札・本文。worktree の先頭なら、その Claude の箱（状態・最後の行・タブへ）。
- 下にファイルの一覧（変更の量つき）と差分。`Enter` で差分を横並びに広げ、`Esc` で戻る。
- WIP の行: 「<ブランチ> の未コミットの変更」、worktree のフォルダ、最後の書き込みの時刻、Claude の箱。「ここでは読むだけ。ステージとコミットは「変更」（2）で。」
- 差分は単語単位で強調する（similar の `from_unicode_words`。足りなければ漢字・かな・英数・記号の種類で区切る）。
  改行だけの差は畳んで印を出す（`core.autocrlf` に従う）。UTF-8 でないファイル（Shift_JIS など）は文字コードを判定して読む。
- マージのコミットの差分は、2 回目の「ブランチ全体の差分」と同じ形にする。

## 変更（`2`）

2 回目の画面イメージで描く。決まっていること:

- 上で worktree を切り替える。ファイルの一覧とステージ。hunk・行の単位でステージできる（patch を作って `git apply --cached`）。差分は横並びと縦並びを切り替える。
- **行のステージはこの画面だけ。**樹形図は読むだけ。
- **Claude が書いている途中（● 実行中）の worktree も止めない。**ステージとコミットの前に「Claude が書いている途中です」と出して確かめる。
- コミットの文、amend（push 済みなら履歴の書き換えになることを先に出す）。

## worktree（`3`）

- 上: 「worktree」・「tsumugi · 4 本 · Claude 3 人」・「⟳ 読み直す」・「＋ 新しい作業 `N`」。
- 表の列: ブランチ・フォルダ｜Claude（tsumugi）｜main から（↑進み ↓遅れ）｜未コミット｜見ていない｜レビュー｜衝突の予測｜操作。
  - 操作: main の行は `pull` `p`・樹形図で見る `Enter`。ほかは 差分 `d`・main を取り込む `m`・PR・消す `x`。
  - Claude の列: 状態の札（● 実行中・◐ 待ち・✓ 済み・失敗）と、その状態になった時刻、Claude の最後の行（待ちなら聞いていることをそのまま）、
    「タブ N · 題 へ `o`」。1 つの worktree に何本もあれば、待っているものを先にして数を添える。読み取り専用（`read_only`）のセッションには、指示を送れない印。
  - レビューの列（#94）: そのブランチの main との差分の確認の状態。未確認（開いていない）・確認中（開いた、または一部のファイルに確認の印）・
    指摘済み（`g` で Claude にメモを渡した後、コミットが進むまで）・承認（差分の全ファイルに確認の印）。下に「確認した数 / ファイル数」。
    変えるファイルは印が外れるので、承認はコミットが進むと戻る。差分の無いブランチは「—」。コミットされた分だけを数える（未コミットは数えない）。
  - 960 では表をカードにする。
- 下の左: **ぶつかりの予測**の表（worktree × worktree、数はぶつかる箇所の数）。押すと、ぶつかるファイルと箇所の数を下に書く。
  未コミットの変更を数えてぶつかる組は黄の点線の枠。マージ中は「予測は衝突の解消（4）の実物に変わりました」。
- 下の右: **見ていない変更**（この表を最後に開いたときから増えたコミット。樹形図で選ぶと消える）。

### Claude の状態の取り方

- `tsumugi ls --json` を、窓が前にあるときは 2 秒、後ろにあるときは 10 秒ごとに呼ぶ（ワーカースレッド）。プロセスの起動が重ければ、
  tsumugi のサーバに ito-ipc でつないで変化を受け取る形に移る。
- セッションの `cwd` が worktree のフォルダの中にあるものを、その worktree のものとする。Windows では大文字と小文字・区切りの文字をそろえて比べる。
- 出すもの: 状態（`waiting`・`waiting?` は待ち、`running` は実行中、`done` は済み、`error` は失敗）、`since_ms`、タブの題。
- tsumugi が動いていなければ列ごと消すだけで、エラーにはしない。
- 「タブへ」は `tsumugi focus N`（tsumugi に足す。tsumugi の TODO.md にある）。

### 衝突の予測

- 範囲: 「各ブランチ × main」と「worktree のブランチどうし」（N 本で N(N−1)/2 組）。
- 2 本ずつ合わせてみる。作業フォルダには触らない。gix-merge で計算し、`git merge-tree --write-tree` を正解として突き合わせるテストを持つ。
- **未コミットの変更も数える。**作業フォルダの中身から一時の tree を作り、ブランチも index も動かさない。
- 計算し直すのは、fetch のあと・どれかの HEAD が動いたとき・作業フォルダが書き換わって 2 秒たったとき。

### 新しい作業（`N`）

- 欄: ブランチ（既定 `tsumugi/MMDD-HHMM`。フォルダはリポジトリの横の `<リポ名>-<ブランチの / を - に>`）、
  元（`origin/main`（何分前に fetch）・`main`・選んでいるコミット）、指示（空なら claude を始めるだけ）、本数（1〜8。2 本以上はブランチに `-1` `-2` …）。
- 「回すもの」の欄に、回すコマンドをそのまま見せる: `tsumugi new <リポ> --worktree <ブランチ> --from <元> -- claude "<指示>"`
  （`--worktree` と `--from` は tsumugi に足す。tsumugi の TODO.md にある）。`Ctrl+Enter` で始める。
- worktree を作るのは tsumugi。置き場の決まり、作った worktree の覚え書き、最後のセッションが終わったときに外すかを聞く流れを tsumugi の 1 か所に残す。

### worktree を消す（`x`）

フォルダを消し、ブランチは残す。確かめの窓に書くこと: Claude のタブが動いていれば先に閉じる（`tsumugi close N`）、
未コミットの変更（消すと戻せない。退避は「取り返せる」の節）、push 済みか・push していないコミットの数（ブランチには残る）。

## 衝突の解消（`4`、衝突している間だけ）

コンフリクトが苦手、という所がこのアプリの一番の狙い。3 方向を 1 画面に並べ、箇所ごとに 1 押しで進める。

- 左の列: 「ぶつかったファイル」（残りの数、解けたら ✓）、「自動で合わせた」（ファイルと理由）、「マージ」（何をどこへ、base と始めた時刻、
  「自分」と「相手」が何か）。
- 上の帯: 「<相手> を <自分> にマージ中」・「残り 2 / 4 か所」・「Claude に渡す」・「マージ全体を中止」（押すと帯の中で確かめる。
  「main を <hash> に戻します（`git merge --abort`）。解いた N か所も捨てます。」）。
- 箇所ごと: 「1 / 4」・ファイルと行・状態・「base を見る / 隠す」。その下に**意図**の行（自分と相手それぞれ、そこを変えたコミットのハッシュ・説明・作者・日時。
  `git log -L` で引く）。3 列（自分・base・相手、前後の同じ行は畳んで「… 同じ N 行 …」）。**結果**の欄はそのまま書き直せ、ボタンは結果を埋めるだけ。
  ヒントの行（例: 両方が同じ番号の節を足したときの「両方を採って相手を 18.16 に」）。ボタン: 自分を採用 `o`・相手を採用 `t`・両方 `b` `B`・base に戻す。
  選ぶと次のまだの箇所へ進む。
- ファイルごとに「このファイルを最初から」。
- **rerere**: 前に同じ形を解いていれば当てておき、「↺ 前に解いた形」の札と「確かめた `Enter`」「忘れる（`git rerere forget`）」を出す。確かめるまで印が残る。
  有効にするのは、初めて衝突を開いたときに聞いて、リポジトリの設定（`rerere.enabled`）に書く（端末から打った `git merge` でも当たるように）。
- 全部解けると下にコミットの欄（`Merge branch '<相手>'`）と「コミット `Ctrl+Enter`」。当てた形を確かめていなければ、その数を出す。
- **3 方向で表せない衝突**（削除と変更・rename どうし・バイナリ・改行だけの差・モードの変化・submodule）は、v1 は「どちらのファイルを取るか」と「外部ツールで開く」だけ。
- **Claude に渡す**: 送る先を選ぶ（その箇所を書いた Claude のタブ、または新しいタブで claude を始める）。3 方向の内容と意図はファイルに書き出し、
  `tsumugi send N` でパスと頼みごと（「両方の意図を残して解き、git add まで。コミットはしない」）を渡す。新しいタブは `tsumugi new <リポ> --name … -- claude …`。
  渡したあとは、ファイルの監視（300 ms）で衝突の印を読み直して残りの数を減らす。`tsumugi ls --json` でその Claude が待ち・済みになったら知らせ、
  確かめるのは人。`tsumugi wait` で待って止まらない。結果は必ず差分で見てから確定する。
- **マージ中に止める操作**: その worktree では HEAD と index を動かす操作（pull・checkout・rebase・merge・cherry-pick・stash・reset・マージ以外のコミット）を止め、
  ボタンを薄くする。押すと理由をトーストで出す（ブランチは作れるが切り替えは止める、など）。読むこと・fetch・push・ほかの worktree の操作はそのまま。
  タイトルバーに「· マージ中」。

## 日々の基本の操作

段階 2「変える」で入れる（cherry-pick は段階 3、rebase の画面は段階 5）。

| 操作 | 中身 | 呼ぶ git |
| --- | --- | --- |
| stash | 一覧と、それぞれの中身を差分で見る。当てる・取り出す・捨てる。捨てる前に退避する。 | `stash list`・`show -p`・`apply`・`pop`・`drop` |
| 直前のコミットを直す | 題と中身を直す。push 済みなら、履歴の書き換えになることを先に出す。 | `commit --amend` |
| cherry-pick | 樹形図でコミットを選び、今のブランチに持ってくる。衝突したら衝突の画面に入る。 | `cherry-pick` |
| revert | 選んだコミットを打ち消すコミットを作る。マージのコミットは、どちらの親に戻すかを選ぶ。 | `revert`（`-m`） |
| タグ | 作る（注釈つきか軽量か）・消す・push。札は樹形図に出る。 | `tag`・`push origin <tag>` |
| 変更を捨てる | ファイル・hunk・行の単位で。捨てる前に退避する。 | `restore`。hunk と行は patch を作って `apply -R` |
| 片付け | マージ済みのブランチ、origin で消えたブランチ、フォルダが無くなった worktree を一覧にし、選んでまとめて外す。未コミットの変更がある worktree と、Claude が動いている worktree は外さない。マージされていないブランチ（squash でマージした PR など）は、先の点を退避してから外す。 | `fetch --prune`・`branch -d`／`-D`・`worktree remove`／`prune` |
| コミットを整える | PR の前に、まとめる（squash・fixup）・題を直す（reword）。rebase の画面で行ごとに選ぶ。 | `rebase -i`（todo は `GIT_SEQUENCE_EDITOR`、題は `GIT_EDITOR` で渡す） |

## ブランチ全体の差分（2 回目で描く）

Claude が終えたブランチを、マージや PR の前に michi の中で見て確かめる画面。GitHub の「Files changed」と同じ形で、手元だけで済む。
読むだけなので、段階 2「変える」の最初に作る（worktree の表の `d`）。

- 範囲は `main...<ブランチ>`（分かれた点から）。未コミットの変更も含めるかを切り替える（既定は含める。Claude はコミットせずに止まることがある）。
- 左にファイルの一覧（変更の量つき）、右に差分。ファイルごとに「見た」の印。印はパスと中身（blob の id）で覚え、見たあとに変わったファイルは印が外れる。
- 「前回から」: 最後に見たときの状態（未コミットの変更ごと一時の tree にして）を覚え、そこからの差分に切り替えられる。
- 指摘を返す: 行にメモを付け、まとめてそのブランチの Claude に送る（ファイルに書き出し、`tsumugi send` でパスを渡す）。
- 次へ: この画面から「マージ」か「PR を開く」（PR は michi では作らず、minato かブラウザに渡す）。衝突の予測もこの画面の上に出す。
- 「見た」の印は michi の状態のフォルダ（リポジトリの外）に、リポジトリとブランチごとに置く。作業ツリーの中に置くと Claude の差分に混ざる。
  前回見た tree だけは、gc で消えないよう `refs/michi/seen/<ブランチ>` に置く。

## rebase（2 回目で描く）

コミットを並べ替える画面（ドラッグとキー）。まとめる・題を直すもここで。途中で止まった状態を帯で常に示す。

## 取り返せる

reflog が戻せるのは ref の動きだけ。それ以外は操作の前に `refs/michi/backup/<日時>` へ退避する。

- `reset --hard`・`restore`（変更を捨てる）の前: `git stash create` の結果。
- `stash drop` の前: 捨てる stash のコミット。
- マージされていないブランチを消す前: その先の点。
- `clean` の前: 未追跡のファイルは `stash create` に入らないので、別に退避する。

確かめの窓に、何が失われるかと、どこに退避したかを書く。

## 作業中の Claude とぶつからない

- 読むための git は `GIT_OPTIONAL_LOCKS=0` で呼び、`index.lock` を取らない（取ると Claude の `git add` が落ちる。tsumugi#142 と同じ問題）。
  gix の status は index を書かない。
- 変える操作は、その worktree で Claude のセッションが動いているとき（`tsumugi ls --json` の `cwd` と `state`）に確かめる。
- 外からの変化はファイルの監視（notify）で拾い、300 ms 静かになったら読み直す。監視できない場所（ネットワークのドライブ）は間を置いて読む。

## gix と git コマンドの分担

方針は「読む・見せる・計算するのは gix、状態を変える操作は git コマンド」。gix を選ぶのは、C のライブラリ（libgit2）を抱えず、
プロセスを起動せずに履歴を構造のまま読め、作業ツリーに触れずにマージを計算できるから。gix は未完成で API も動くので、
最初は git コマンドだけで作り、樹形図の読み込みと衝突の計算から gix に置き換えてよい。

| 操作 | 方針 |
| --- | --- |
| 履歴の読み込み・樹形図・merge-base・ref | gix（ahead/behind は大きなリポで重くなりうる） |
| status・差分 | gix（index を書かない） |
| blame | gix。名前の変更をまたぐときは `git blame`・`git log --follow` |
| マージの計算（予測・衝突の画面の 3 方向） | gix-merge。正解は `git merge-tree --write-tree` |
| commit の作成 | `git commit`（hooks と署名を走らせるため） |
| 行・hunk のステージ | patch を作って `git apply --cached` |
| worktree の作成 | tsumugi（`tsumugi new --worktree`）。削除・修復は `git worktree` |
| push・fetch・checkout・switch・restore・reset・merge・rebase・cherry-pick・revert・stash | git |
| rerere | git の `rerere.enabled` |

gitoxide の crate-status.md（2026-10-15）で確かめた。

### git の呼び方

- 最低の版は **2.38**（`merge-tree --write-tree`。zdiff3 は 2.35）。起動時に確かめ、足りなければ使えない機能を出す（macOS の Xcode の git は古いことがある）。
- `GIT_TERMINAL_PROMPT=0` で呼ぶ。Windows の Git Credential Manager の窓はそのまま出し、ssh の passphrase は ssh-agent を案内する。
- push・fetch は進み具合（`--progress`）と取り消しを出す。
- 呼ぶのは全部ワーカースレッド。UI スレッドではディスクにもプロセスにも触らない。古い依頼は捨てる。

### 最初の試作で確かめること

- 予測が実際の `git merge` と同じ衝突になるか（rename の検出、`.gitattributes` のマージドライバ、`merge=binary` で食い違いうる）。
- 大きな履歴の速さ。目標は 10 万コミットで最初の画面まで 0.3 秒。

## ito-graph（樹形図は ito のクレート）

- レーンの割り当て・色・行の高さ・曲線の経路は egui に依らない層、描画は egui の層（feature）に分ける。
- 入力は「コミットの id・親・札のリスト」だけで、Git のライブラリに依らない（minato の PR の履歴や tsumugi のセッションの分岐にも流用できる）。
- トポロジカル順に少しずつ受け取り、上から順にレーンを決める（仮想スクロールと両立させる）。入力は「見せる行と、見せる親」。
  絞りや畳みで親を付け替えるのは Git 側（michi-core）で計算する。

## 他のアプリとのつなぎ

- **Claude へ**: tsumugi の CLI（`ls --json`・`send`・`read`・`wait`・`new`・`close`、足すもの `focus`・`new --worktree --from`）をプロセスとして呼ぶ。
  tsumugi が動いていないとき・セッションが読み取り専用のときの表示を用意する。長い本文は打ち込まず、ファイルに書き出してパスだけ渡す。
- **michi へ**: kura から「このフォルダを開く」、minato から「この PR のブランチを開く」。ito-ipc の上に小さな約束を作り、michi を最初の利用者にする。
  最初は michi の中で「`michi open <path>` が起動中の michi に渡す（無ければ新しく開く）」を作り、kura・minato が受け口を持つ番になったら ito に移す。
